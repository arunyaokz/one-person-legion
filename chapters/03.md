# 第 3 章　同一个 Bot，换一张单子就像换了个人

> 本章类型：操作指南。照着做完，你会有一张能反复用的派单模板，同一张单子连派 3 次，交回来的格式一样，Bot 不用回头追问你。

## ① 一句话结论

派单写清五件事：要什么结果、从哪找料、什么不能碰、交成什么样、停在哪等你。再加两句话：「有疑问就问，问到完全理解再做」，「交给我之前，先按我的标准自查一遍」。

单子上少写一件事，它就按自己的猜测补上那一件，每次猜的还不一样。

## ② 我遇到的事

【补：你记得最清楚的一张「坏单」原话是什么，比如「帮我整理一下今天的哈萨克斯坦新闻」，当时 Bot 交回来的是什么样】

【补：同一件事你后来改写成什么样的单子，交回来的东西差在哪里。前后大概返工了几轮】

我把那张单子重读了一遍，发现【补：缺了哪几格】都没写。我脑子里有一张完整的图：要几条、从哪来、用什么格式、哪些不能写。写进单子的只有一句话，剩下的 Bot 只能猜。

## ③ 怎么做

### 为什么一句话的单子不够

Anthropic 做多 Agent 调研系统时踩过类似的坑。他们的情形是主 Agent 给子 Agent 派单，和你给 Bot 派单有些像。主 Agent 起初给下属的指令很短，比如「研究半导体短缺」，结果下属理解偏了：一个去查 2021 年的汽车芯片危机，另外两个重复查 2025 年的供应链，分工落空。他们的结论是，每个下属需要一个目标、一个输出格式、用哪些工具和来源的指引，以及清楚的任务边界；少了这些，Agent 会重复干活、留下缺口，或者找不到该找的信息 [1]。

Grok Bot 官方文档给的「好的第一单」示范，也拆成同样几块：做什么、在哪做、带上哪些背景、做完是什么样 [2]。

下面引用的 Anthropic 文档是写给 Claude 的，我只借其中通用的写指令原则，不当作 Grok Bot 的行为说明。

还有一个检验办法。Anthropic 的提示词指南建议，把你的指令拿给一个不了解这件事的同事看，让他照着做；他会困惑的地方，模型也会困惑 [3]。派单前我会把单子拿给不了解背景的人读一遍，看他会在哪里卡住。

### 五要素，逐条写

**1. 结果：要什么，做到什么算完。** 写成一个能检查的交付物，不写成方向。「关注一下政策动态」是方向；「挑出今天新发的 3 到 5 条政策新闻，每条一句话说明为什么和资讯站读者有关」是结果。条数、范围、时间窗口写清楚，Bot 才知道什么时候该停。

**2. 来源：从哪找，找不到怎么办。** 写明可以用哪些来源，优先哪一类。Anthropic 的测试人员发现，早期的 Agent 总选排名靠前的内容农场，不选排名靠后但更权威的来源，他们在提示词里加了来源质量的规则，情况有所改善 [1]。资讯站的单子里我会写：只用政府官网和官方通讯社，转载稿要追到原发。

还要写来源缺了怎么办。官方文档建议设例行任务时确认「来源缺失时怎么处理」，示例大意是：数据拿不到时报告失败，不要拿旧数据凑 [4]。手动派单也照这样写。

**3. 禁区：什么不能碰。** 列出它这一单不能做的动作。官方文档建议，这几类动作要在请求里写明边界：发消息、发布内容、购买和转账、删除或覆盖数据、改权限、改生产环境、接受法律条款 [5]。资讯站的单子里，禁区一般是：不发帖，不联系任何人，不改候选表以外的文件，不写原文里没有的数字。

禁区之外，我会写一句为什么。Anthropic 的指南里有个例子：只写「不要用省略号」，不如说明「回复会被语音朗读，朗读引擎读不出省略号」，模型能从理由里推出更多该避开的情况 [3]。我写「不写原文里没有的数字」时，会补一句「资讯站每个数字都要能点开出处」。

**4. 交付格式：交成什么样。** 写清文件类型、字段、存在哪、多长。Anthropic 的指南建议明确写出你要的输出格式和限制，顺序重要时用编号步骤 [3]；它还建议说你要什么，少说你不要什么 [3]。最省事的做法是直接给一个样例：表头写好，填一行示范，让它照着填。

**5. 停点：做到哪一步停下等你。** 写明它交到哪一步就停，停下时给你看什么。官方文档的示例是这样写的：核对数据，起草一份预算调整建议，不改投放、不联系代理商，先把当前值、建议值和预期影响列给我，再请我批准 [5]。这句话里有停点，也写了停下时要交什么材料，你批不批有依据。

资讯站的停点一般是：候选表写好就停，把文件路径和一句话摘要发给我，等我回「批准」或「退回」。

### 再加两句话

**「有任何不清楚的地方，先问我，问到完全理解再做。」** 这句是本书的措辞。Nate Herk 在公开课程里派单时加过一句类似的话，大意是有问题就问我，问到你理解为止（原话是 ask me questions until you understand）。他还说，不给清晰的完成标准，交回来的东西往往很差；Bot 会一直追问，直到对你要的东西理解得好很多 [6]。它问的问题，就是你单子上漏写的部分。把答案补回单子里，下次就不用再答一遍。

**「交给我之前，先按我的标准自查一遍。」** Nate 把这叫验证循环：像管员工一样，让它交付前先自查，不收第一版，让它自己改几版再交 [6]。Anthropic 的指南也建议在指令末尾加一句「完成前，按某某标准核对你的答案」[3]。自查要给标准，不然它只会回一句「已检查」。资讯站的自查标准就是交付格式那一栏：每条能点开原文，日期在时间窗口内，没有原文以外的数字。

Anthropic 在提示指南里说，他们的 Opus 5 不加这句也会自查，硬加会多花 token [3]。这是他们在自家模型上测的结果，是否适用于你用的模型，要自己测。我的做法是先加上，跑几次看它交回来的错误还多不多，再决定这句留不留。

### 连跑三次，看格式

同一张单子，派三次。不看措辞是否相同，看格式是否一样、它有没有回头问你。

为什么是三次？三次是我定的最低次数，不是 Anthropic 的数字。Anthropic 在同一篇文章里写过，Agent 每次运行的决策都可能不同，提示词一字不改也一样 [1]。跑一次碰巧对了，说明不了单子写得好。三次格式一致、没有追问，单子才算立住。哪一次走样，就去找单子上哪一格写得含糊，先改单子；单子没问题还走样，再看是不是 Bot 或技能的问题。

## ④ 模板或对照

### 派单模板（templates/dispatch.md）

```markdown
## 派单：{一句话任务名}

1. 结果：{交付物是什么，几条，范围，时间窗口，做到什么算完}
2. 来源：{可以用哪些来源，优先哪类}；来源打不开时：{报告失败，不用旧数据}
3. 禁区：{这一单不能做的动作}。原因：{一句话}
4. 交付格式：{文件类型、字段、存放位置、长度}，样例如下：
   {表头 + 一行示范}
5. 停点：做到 {哪一步} 停下，把 {要给我看的东西} 发给我，等我回「批准」或「退回」。

有任何不清楚的地方，先问我，问到完全理解再做。
交给我之前，按第 4 条的格式和下面的标准自查一遍：{两三条能一眼判断的标准}
```

### 好单和坏单并排对照

| 要素 | 坏单 | 好单（资讯站示例） |
|---|---|---|
| 结果 | 整理一下今天的哈萨克斯坦新闻 | 挑出过去 24 小时新发的 3 到 5 条政策新闻，每条一句话说明和资讯站读者的关系 |
| 来源 | 没写 | 只用政府官网和官方通讯社，转载稿追到原发；官网打不开就报告，不用昨天的数据 |
| 禁区 | 没写 | 不发帖，不联系任何人，不改候选表以外的文件，不写原文里没有的数字。原因：资讯站每个数字都要能点开出处 |
| 交付格式 | 没写 | 一个表格文件，四列：标题、发布日期、原文链接、一句理由；附一行示范 |
| 停点 | 没写 | 表格写好就停，把文件位置和三句话摘要发给我，等我回「批准」或「退回」 |
| 两句话 | 没有 | 有疑问先问到完全理解；交付前按四列格式和「链接能打开、日期在 24 小时内」自查 |

坏单这一列没写的格子，Bot 通常按自己的理解补上，比如去翻新闻聚合站、写成长稿。发消息、发布这类动作，要在单子里写明边界 [5]。

## ⑤ 做到什么算过

- 你按模板写好了一张单子，五格都填了，两句话都在。
- 同一张单子连派 3 次，交回来的格式和样例一致。
- 3 次里 Bot 没有回头追问；第一次它追问过的内容，你已经补进单子。
- 3 次都停在你写的停点，没有越过禁区。

## ⑥ 常见坑

1. **只写结果，不写停点。** 比如它可能把候选表做完，顺手就去发帖，因为单子上没说停在哪。怎么办：每张单子最后一格都写「做到哪一步停下，给我看什么」。
2. **禁区只写「别乱来」。** 它不知道什么算乱来。怎么办：按官方列的几类动作逐条写，发布、发消息、删除、花钱，用得上的都列出来 [5]。
3. **格式用嘴描述，不给样例。** 「整理成表格」可以有十种表格。怎么办：直接给表头和一行示范。
4. **它追问了，你只在聊天里答，不改单子。** 下一次它还会问同样的问题，或者不问，照旧猜。怎么办：每次追问的答案都写回模板。
5. **跑一次对了就当单子写好了。** 每次运行的决策都可能不同 [1]。怎么办：连跑三次，填记录表。

课后检查：翻出你最近一次对 Bot 不满意的那条消息，按五格拆一下，看哪一格是空的。那一格你心里有答案吗？有答案没写下来，是单子的问题；自己也没想清楚，先别派这一单。
