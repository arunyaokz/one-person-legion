# 第 0 章　我每天只回两个字：批准，或者退回

> 本章类型：解释。讲清楚这本书要搭的是什么，以及人在里面做什么。第 1 章讲基本概念，具体操作从第 2 章开始。

## ① 一句话结论

一个人，加一个幕僚长做入口，再加几个只管一件事的 Bot，就能把日更变成一条流水线。人只在两个点出手：早上批准选题，发布前批准成稿。其余时间，人不碰稿子。

读完这一章，你应该能用自己的话说出三个词：入口、专线、拍板。后面 15 章都在讲怎么把这三个词落到地上。拍板最大的风险，是变成橡皮图章。

## ② 我遇到的事

【时间】，我开始给一个哈萨克斯坦资讯站做日更。【坚持了多久】之后，更新断了。

断掉的原因，我当时以为是没时间。后来回头看，我每天花在写作本身上的时间只有【大约多少】，其余时间都耗在切换上：从找料切到核实，从核实切到改稿，从改稿切到做图，再切到发帖。每切一次，我都得重新想一遍「这条消息的出处是哪」「上一版改到哪了」。【补一个具体的断更当天：那天卡在哪一步、为什么】

后来我换了做法：只留一个入口，叫它幕僚长；找料、核查、写稿、做图，各交给一个 Bot。我每天只看两次：早上看选题单，回「批准」或「退回」；发布前看成稿，再回一次。【补：换做法后第一周的真实情况，包括出过的错】

这里先说清楚一件事：Bot 没有把我变成一个更勤快的人，它只是让我不用再当搬运工，只当拍板的人。这两种角色消耗的东西不一样：搬运耗的是时间，拍板耗的是注意力。这一章后面会讲，注意力是这条流水线里最容易被高估的一环。

## ③ 怎么做：三个词

### 入口：只有一个，叫幕僚长

所有任务从幕僚长进，所有结果从幕僚长出。我不直接给专线派活，也不直接收专线的稿子。

为什么只留一个入口？因为多个 Bot 各自理解你的意思，理解会分叉。Cognition 的工程师 Walden Yan 在 2025 年 6 月写过一篇《Don't Build Multi-Agents》，他举的例子是让两个子 Agent 分头做一个 Flappy Bird 游戏：一个做出了马里奥风格的背景，另一个做出的小鸟和游戏不搭。他的结论是，每一个动作都隐含一个决定，决定分散在不同 Agent 手里，结果就会互相打架 [1]。

他的建议是尽量用单线程。我没有完全照做，因为日更里找料、核查、做图确实是分得开的活。我的折中办法是：决定只在幕僚长那里做，专线只执行，不替别人做决定。

Anthropic 在 2025 年 6 月公开了他们多 Agent 研究系统的做法，结构也是一个主 Agent 带一组子 Agent。他们写到，主 Agent 给子 Agent 派活时，要写清目标、输出格式、该用的工具和来源、任务边界；早期只写一句「去研究芯片短缺」，几个子 Agent 就重复搜了同一块内容 [2]。这四样东西，就是第 3 章派单五要素的来源之一。

### 专线：一个 Bot 只管一件事

以资讯站为例，我的专线是这样分的：

| 专线 | 只管一件事 | 不碰什么 |
|---|---|---|
| 找料 | 按清单盯来源，交候选消息和原始链接 | 不改写，不判断真假 |
| 核查 | 给每个事实标出处和来源等级 | 不改文风 |
| 写稿 | 按核查后的事实写正文 | 不新增事实 |
| 做图 | 按正文出配图 | 不往图里加正文没有的信息 |

【补：你实际有几条专线，名字叫什么，和上表有哪些不同】

为什么要窄？加州大学伯克利分校的团队分析了 7 个开源多 Agent 框架的 1,642 条运行记录，归出 14 种失败方式，分成三类：任务规格与系统设计问题、Agent 之间对不上、核查不到位 [3]。在他们测的几个框架里，任务失败率在 41% 到 86.7% 之间。

其中一个案例单独拿出来看：他们只改了 ChatDev 里各角色的职责说明，模型和用户输入都没动，任务成功率提高了 9.4% [3]。职责写清楚，本身就是一种能力。

窄还有一个原因：贵。Anthropic 的数据是，单个 Agent 用的 token 大约是普通聊天的 4 倍，多 Agent 系统大约是 15 倍 [2]。他们产品里的数字不能直接套到你的账单上，但方向是一样的：每多一个 Bot，每多一轮来回，都在花钱。这也是第 2 章劝你别一上来就建十个 Bot 的原因。

### 拍板：人只在两个点出手

这就是本章标题的意思。我每天只回两个字，「批准」或「退回」，退回时再加一句理由。

两个点放在哪？我的原则是：放在动作收不回来之前。OpenAI 在《A practical guide to building agents》里列了两种该叫人介入的情况：一是 Agent 重试超过上限，二是动作敏感、不可逆或者代价高，在你对它的可靠性有把握之前，要人来把关 [4]。资讯站里，发出去的帖子收不回来，所以发布前必须拍板一次；选题是另一个点，因为方向错了，后面每一步都在白干。

LangGraph 把这种设计做成了框架里的标准动作：流程停在关键步骤前，等人回「是」或「否」再往下走；它的人工审核中间件还多给了「编辑」和「直接回复」两种选项 [5][6]。

我只用两个字，没有用「编辑」。原因是：我一动手改，就又变回了写稿的人，下次 Bot 还会犯同样的错。退回时我写一句理由，让专线自己改，改的方法再写进技能（第 12 章）。【确认：这是否是你不用「编辑」的真实原因】

### 拍板最大的风险，是你变成橡皮图章

这一节是我写这本书时查资料查出来的，也是我认为整章最该记住的一段。

人机交互研究里有一个词，叫自动化偏差。Parasuraman 和 Manzey 在 2010 年综述了这方面的实证研究，结论有三点：人在同时处理多件事时，会放松对自动系统的检查；新手和专家都会这样；靠培训和提醒防不住，团队一起决策也会出现 [7]。

欧盟《人工智能法》第 14 条讲人类监督，专门写了一款要求：负责监督的人要能意识到自己可能过度依赖系统输出，也就是自动化偏差 [8]。这条法规管的是高风险 AI 系统，不管一个资讯站。我引它，是因为立法者也承认：把人放进流程里，不等于人在起作用。

所以「批准」这两个字的分量，取决于你批准时看了什么。我给自己定了一条规矩：幕僚长交来的每一张批准卡，我至少看三样东西，看不到就退回。三样东西写在下面的模板里。【确认：这三样是否就是你实际在看的】

伯克利那篇论文还发现，很多框架里专门做核查的 Agent 也只查表面，比如代码能不能编译，有没有留下待办注释 [3]。核查 Bot 不能替你拍板，它只能让你拍板时少看一些。

## ④ 模板或对照

### 一天时间线（示意）

以下时间是示意，按你自己的发布时间倒排（第 8 章）。

```
时间（示意）  谁在干活            人在做什么
--------------------------------------------------------
夜间          找料专线盯来源        睡觉
07:30         幕僚长交选题单        ★ 拍板 1：批准 / 退回选题
08:00-11:00   核查 → 写稿 → 做图    不碰稿子
11:30         幕僚长交成稿批准卡    ★ 拍板 2：批准 / 退回成稿
12:00         按批准发布            不再改动
晚上          各专线交一条经验      看一眼，不回也行
```

【补：你真实的一天时间线，哪两个点出手，各花几分钟】

### 批准卡（幕僚长交给我的格式）

```
[编号] 幕僚长｜待批准｜交给：我
标题：
发到哪里：
改动了什么（相对上一版）：
事实与出处：每个数字一行，带链接和来源等级
风险点：有没有涉及人名、机构、未证实消息
请回：「批准」或「退回：一句理由」
```

我看的三样东西：每个数字有没有出处；有没有正文里没有、图里却有的信息；发出去以后有没有收不回来的风险。

### 退回的写法对照

| 坏的退回 | 好的退回 |
|---|---|
| 「不行，重写」 | 「退回：第二段的汇率没有出处，换成央行当天公布的数」 |
| 我自己动手改完再发 | 写一句理由，让写稿专线改，改法记进经验库 |
| 「差不多，先发吧」 | 看不到三样东西，就退回 |

### 30 秒上手

1. 先别建军团。挑一件你每天重复做、做完要你点头的小事（第 2 章）。
2. 给一个 Bot 写一张单子：要什么结果、从哪找、哪些不能碰、交什么格式、停在哪等你（第 3 章）。
3. 让它只交草稿，你回「批准」或「退回」。连续做对三次，再让它每天自己跑（第 4 章）。

| 篇 | 章 | 你会得到 |
|---|---|---|
| 一　看到结果 | 0–1 | 知道要搭什么，懂四个基本概念 |

## ⑤ 做到什么算过

- 你能用一句话分别说出入口、专线、拍板是什么，不看书。
- 你能在自己现在的工作里，指出两个动作收不回来之前的点。那就是你的拍板点。
- 你能说出，自己批准一张稿子时至少要看哪三样东西。

## ⑥ 常见坑

1. **批准变成了习惯动作。** 连着十天都没问题，第十一天你会不看就批。怎么办：批准卡缺任何一样，直接退回，不看内容。
2. **一上来就建十个 Bot。** 每个 Bot 都在花额度，决定也会散在各处。怎么办：从一个 Bot、一件小事开始（第 2 章）。
3. **让 Bot 互相批准。** 核查 Bot 说「没问题」，幕僚长就发了。怎么办：对外发布只认你本人的原话「批准」（第 10 章）。

最后留一个问题给你。把你每天做的事列出来，每一件问自己：这件事要的是我的手，还是我的判断？要手的，可以交出去。要判断的，留给自己，然后想清楚，你在判断时到底看了什么。想清楚要交出去什么之后，下一章我们看看 Bot 手里到底有什么，能替你接住这些活。
