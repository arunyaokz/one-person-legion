# 第 8 章　先定发布时间，再把流水线倒着排

> 本章类型：操作指南。把选题、核查、写稿、做图和发布接成一条线，再从自己的发布时间倒排，留出批准、退回和补救的位置。

## ① 一句话结论

先定你什么时候发，再倒着排每一棒什么时候交、交什么、交给谁；选题和成稿停下来等本人批准，没赶上就不发，别让下一棒拿半成品继续跑。

## ② 我遇到的事

【补：你实际做日更时，哪次各个 Bot 都干了活，最后却没赶上发布时间；卡在哪一棒，怎么发现的】

【补：你后来怎样倒排时间，选题和成稿分别在哪里等你批准；改完后实际发生过什么，包括出错或退回的情况】

单个岗位会干活，不等于整条线能准时交付。上游晚交，后面每一棒都得跟着挤；到了发布前才发现缺出处，就没有时间补了。

## ③ 怎么做

### 先画交接，不急着定时

把你要发的东西写在最右边，再往左问：发之前要有什么？那份东西从哪里来？谁交给谁？资讯站可以先画成这样：

```text
候选消息 → 选题批准 → 核查 → 翻译 → 短稿、配图 → 成稿批准 → 发布
```

这是示例，不是每个人都要建齐这些岗位。没有翻译需求，就删掉翻译；没有配图，就删掉配图。Anthropic 建议先找最简单的方案，需要时再增加复杂度 [1]。

每一棒只定一个负责人，写清输入、交付物和交给谁。交付物最好有固定的文件位置，别让下一棒去群聊里翻全文。群里沿用第 7 章的格式，交接细节走私聊。

### 从发布时间往回排

先填你自己的发布时间，再往前填成稿交来的时间。两者之间留给你看稿、退回和重新检查。再往前排写稿、核查、选题批准和找料。每一棒都写「最晚交付时间」，不是只写「上午做」。

时间从哪里来？先用自己的空档估，再拿实际跑过的记录改。不要把每一棒都排到刚好贴边：上游晚了，后面就没有缓冲。选题批准也要放在你能看的时候，不能假设你随时在线。

【补：你自己的发布时间、各棒最晚交付时间，以及实际留给退回和复查的余量】

### 两处停下来，没批准就不往下走

选题交来时，看方向和来源，回「批准」或「退回：理由」。没批准，核查和后续制作不启动。成稿交来时，看事实出处、图文是否一致、发布风险；没收到本人对当前版本的「批准」，就不发布。退回后改了稿，重新交完整成稿和改动说明，再等本人批准。

LangGraph 的文档把等待外部输入设计成可以暂停、恢复的流程 [2]。这是开发框架里的做法；放到这里，借的是「明确停在哪里」这个思路，不代表 Grok Bot 会自动替你实现这道关。要把停下、等待和恢复写进派单，并亲自验证。

### 卡住就退回，赶不上就停

每棒交的时候，负责人检查输入是否完整。缺原始出处，核查退回找料；核查没放行，写稿不自行补事实；成稿缺图或出处，就不交作可批准的完整稿。退回时说清缺什么、交给谁，群里留一行状态，细节私聊。

到了某棒的最晚交付时间还没交，负责人报「卡住」，写明原因和需要谁处理。幕僚长对照发布时间告诉本人：还能否在留出复查时间的情况下完成。不能，就取消或改期；不要因为定时到了就发布旧稿，也不要把没回应当批准。改期后重新倒排，确认用的是哪一版稿。

### 跑通一次，再设定时

先拿一条真实候选手动走完全程，记录每棒的交付时间、退回原因和实际用时。检查批准后再发布的是不是你看过的版本。然后按记录调整时间表，再考虑让找料按时启动。

Grok Bot 的官方文档建议先做一次任务，做可靠后把方法存为技能，再自动化；例行任务可以按时间或事件触发 [3]。定时只负责启动，不等于结果已经核查或获得批准。

## ④ 模板或对照

### 倒排表（示例，时间由你填）

| 顺序 | 最晚时间 | 负责人 | 输入 | 交付物 / 交给谁 |
|---|---|---|---|---|
| 找料 | {时间} | 盯盘 | 来源清单 | 候选及原始出处 / 幕僚长 |
| 选题批准 | {时间} | 本人 | 候选及出处 | 批准或退回 / 幕僚长 |
| 核查 | {时间} | 核查 | 已批准选题 | 核查结果及出处 / 翻译或写稿 |
| 制作 | {时间} | 翻译、短稿、做图各管本岗 | 核查放行的内容 | 稿件及配图 / 幕僚长 |
| 成稿批准 | {时间} | 本人 | 完整成稿、出处、改动说明 | 批准或退回 / 幕僚长 |
| 发布 | {你的发布时间} | 发布负责人 | 本人批准的版本 | 发布结果 / 幕僚长 |

制作涉及多个岗位时，在自己的表里给每个岗位单列交付时间和接收人。倒排时把退回、修改、复查的余量放进时间表；放不下，就提前开始或改发布时间。

### 流水线派单（发给幕僚长）

```text
任务：按倒排表准备 {内容}，目标发布时间 {时间和时区}。
从 {来源清单位置} 找候选，交我批准选题；没批准不启动后续制作。
按倒排表派给各负责人。每棒交文件位置、结果和下一接收人。
缺输入就退回；到最晚交付时间未完成就报「卡住」，说明原因和交给谁。
成稿交我时附出处、配图和相对上一版的改动；等我批准当前版本。
未获批准或赶不上复查时，不发布，报告我决定是否改期。
发布后交发布结果和实际时间，记录各棒用时及退回原因。
```

【补：你实际给幕僚长的派单里，还有哪些与此不同的要求】

## ⑤ 做到什么算过

- **拿一条候选走完全程。** 倒排表每一棒都有负责人、最晚时间、输入和交付去处；实际交付时间也有记录。
- **试一次退回。** 故意拿掉一条出处，核查能退回找料，后续岗位不拿它当放行材料；补齐后再继续。
- **对一遍批准和版本。** 选题、成稿都有本人的明确批准；发布内容与批准的成稿一致。没批准或赶不上复查时，流程停住。
- **拿记录改表。** 看实际用时和退回记录，调整交付时间与余量，下一次按改过的表跑。

## ⑥ 常见坑

1. **只定发布时间，不定交付时间。** 最后知道晚了，却不知道卡在哪。怎么办：倒排每一棒的最晚交付时间和负责人。
2. **选题还没批准就开始写。** 方向一改，后面的活都得重做。怎么办：选题批准前停住；退回后重新交候选。
3. **拿半成品往下传。** 缺出处的内容进了稿，后面的人以为已经核查。怎么办：写清每棒的输入和放行条件，缺一项就退回。
4. **把定时当批准。** 到点启动不代表内容可以对外发布 [3]。怎么办：发布前等本人批准当前版本；没回复就停。
5. **把时间排满。** 退回一次，复查就被挤掉。怎么办：根据实际记录留出修改和复查的余量；放不下就改期。
6. **只测顺利的情况。** 平时能跑，遇到缺出处就不知道球在谁手里。怎么办：拿缺出处的候选试一次退回，检查状态、接收人和恢复条件。

课后检查：看着你的倒排表，随便指出一棒没按时交，你能说出谁报卡、谁接手、什么时候决定改期吗？说不出，就把这几格补上。
