# 第 4 章　连续做对三次，再让它每天自己做

> 本章类型：教程。照着做完，你会有一个存好的技能、一份 5 条小样的试跑记录，以及一个连跑 3 天没跑偏的例行任务。

## ① 一句话结论

手动跑通以后，先把做法存成技能，再拿 5 条小样试跑，5 条全部合格才开例行任务。频率先定低，跑稳了再往上调。

顺序反过来，出错的地方就从聊天框挪到了后台。你在聊天框里能当场看见它出错，后台出错要等你哪天翻记录才看得见。

## ② 我遇到的事

【补：你第一次把一件事直接设成例行任务、没先存技能也没试跑，是哪件事。它在后台跑了几天、出了什么问题、你是什么时候发现的】

【补：后来按「存技能 → 试跑 → 开例行」重走一遍，试跑时挑出了哪一条小样不合格，你改了技能里的哪一句】

我回头看，问题出在我把「它做对过一次」当成了「它会一直做对」。在聊天框里它做对一次，是我盯着、随时纠正的结果。例行任务跑起来的时候，我不在场。

## ③ 怎么做

### 为什么做对一次不够

Anthropic 在一篇讲 Agent 评估的文章里算过一笔账：一个 Agent 单次做对的概率是 75%，连跑 3 次全对的概率只有 0.75 × 0.75 × 0.75，约 42% [1]。他们把这个指标叫 pass^k，意思是 k 次全部成功的概率；k 越大，这个数越低。他们说，用户期望每次都靠得住的场景，看的就是这个数 [1]。

例行任务就属于这种场景。它每天替你跑一次，你不在旁边。做对一次只说明它能做到，要连着做对，才说明你可以不在场。

Grok Bot 官方文档的顺序也是这样：先做一次性的任务，把它做稳，存成技能，然后再自动化 [2]。下面分三步走。

### 第一步：把跑通的做法存成技能

第 2、3 章里，你已经让 Bot 手动跑通了一件事，派单也立住了。这时候在同一个对话里让它存技能，它手上有刚才的全部上下文。

官方文档说，一个有用的技能要写清六件事：什么时候用、需要什么输入和权限、按什么顺序做、怎么验证结果、交回什么、哪些动作要批准 [2]。对照第 3 章的派单五要素，大部分你已经写过了：结果对应「交回什么」，来源对应「输入」，禁区和停点对应「哪些要批准」。存技能时，你要补上的是两件派单里常常不写的事：

- **什么时候用。** 这句是写给以后的 Bot 看的。官方文档说，技能是所有 Bot 共用的一个库 [2]，Bot 靠这句话判断这一单该不该用它。写成「每天找资讯站要用的政策新闻候选时用」，比写成「新闻技能」好判断。
- **出错了怎么办。** 手动跑的时候，出错了你在旁边纠正；技能里要把你当时的纠正写成规则。官方文档讲演示教学时提醒过：从一次演示学出来的技能只是草稿，一次示范里看不出来的判断规则、失败处理和批准边界，要自己补上 [2]。

我存技能时会对它说一句：把刚才我纠正过你的地方，都写成技能里的规则，每条后面写一句原因。原因的作用第 3 章讲过，它能从原因里推出更多该避开的情况。

### 第二步：拿 5 条小样试跑

技能存好了，先别开例行。挑 5 条小样，让它在聊天里按技能各做一遍，你逐条判合格或不合格。

5 条是本书的做法，不是哪份文档给的标准。Anthropic 那篇文章建议，正式做评估时，一开始从真实失败里挑 20 到 50 个简单任务就够 [1]。一个人跑一件小事，用不着那么多；但只试 1 条，它碰巧做对了，你什么也判断不了。5 条是我能每条认真看完、又能看出它稳不稳的数量。你的事情越重要，挑得越多。

挑小样比条数更要紧。Anthropic 的经验是，既要测它该做某件事的情况，也要测它不该做的情况；只测一边，Agent 就会往一边偏 [1]。他们举的例子是搜索：只测「该搜的时候搜没搜」，最后会得到一个什么都去搜的 Agent [1]。

资讯站的 5 条小样，我这样挑：

1. 普通的一天，官网有三五条新政策。看它挑得准不准。
2. 新闻很多的一天。看它会不会超过条数上限。
3. 没什么新政策的一天。看它会不会拿旧新闻凑数。
4. 一条只有转载、找不到原发的新闻。看它会不会追到原发，追不到就不收。
5. 官网打不开。看它会不会报告失败，而不是拿昨天的数据交差。

第 3、4、5 条都是「不该做」的情况。官方文档建议，设例行任务时要写清没数据、数据过期时怎么处理 [2]。这几条小样，就是在它真遇到之前先试一遍。

判合格之前，先写好标准。Anthropic 给的检验办法是：两个懂行的人各自去判，应该得出同一个结论；判不出来，说明任务或标准写得含糊 [1]。标准写成能一眼判断的句子，比如「每条都能点开原文」「日期在 24 小时以内」「没有原文里没有的数字」。

一条不合格，就去改技能，再把 5 条从头跑一遍。只重跑不合格的那条，你不知道这次修改有没有把别的弄坏。

试跑做的是真实操作。官方文档提醒，测试运行会打开网站、改文件、调用连接的工具，所以要用安全的输入，写操作留在批准后面 [2]。资讯站的技能只写候选表，不发帖，试跑时我也只让它写到一个测试文件里。

### 第三步：开例行任务，频率先低后高

5 条全部合格，再开例行。官方文档建议，建例行任务时确认六件事：由哪个 Bot 负责、时间和时区、输入来源、预期结果、批准边界、来源缺失时怎么办 [2]。前面五件，技能和派单里都有了，第六件你在试跑第 5 条时已经验过。

开的时候有三件事要知道：

- **新建的例行任务不会马上跑。** 它等到下一个预定时间才第一次跑；早上 8:05 设「每天 8:00」，第一次是第二天 8:00 [2]。想当场看效果，用测试功能，测试会真实执行一遍 [2]。
- **频率越高，额度花得越多。** 官方文档说，每跑一次都花额度；每小时一次、间隔很短，或者盯着一个热闹的 Slack 频道，一天就能花掉一周的额度 [2]。所以频率先定低，资讯站的盯盘我先定每个工作日早上一次。
- **有上限。** 每个 Bot 最多 50 个例行任务，两次运行至少隔 5 分钟，每个例行任务只保留最近 20 条运行记录 [2]。

开了以后，前 3 天每天看一次它交的东西，对照试跑时的标准。官方文档列了第一次运行后要看的几件事：选的是不是当天的输入、格式对不对、每个动作有没有出处或记录、是不是停在了该停的地方、失败时有没有写清楚 [2]。「连跑 3 天不跑偏」是本书的做法：3 天里有一天它碰上了你没试过的情况，就把那天的情况加进小样，改技能，重新试跑。

3 天都稳了，再考虑要不要调高频率。我调频率只问一个问题：跑得更勤，我会更早做出什么决定？答不上来，就不调。

## ④ 模板或对照

### 存技能前检查单

存之前逐条打勾，有一条空着就先补。前六条对应官方文档的「一个有用的技能要写清什么」[2]，后三条是本书的做法。

```markdown
## 存技能前检查：{技能名}

- [ ] 什么时候用：一句话，写给别的 Bot 看，能判断这一单该不该用它
- [ ] 输入和权限：从哪拿料，要哪个连接或登录
- [ ] 步骤顺序：编号写，每步做完是什么样
- [ ] 怎么验证：两三条能一眼判断合格的标准
- [ ] 交回什么：文件类型、字段、放哪，附一行样例
- [ ] 要批准的动作：发帖、发消息、删除、花钱，用得上的都写上
- [ ] 失败怎么办：来源打不开、没有新数据、数据过期时各怎么做
- [ ] 我纠正过的地方：每条写成规则，后面跟一句原因
- [ ] 已经手动跑通：同一张单子连派 3 次，格式一致、不用追问（第 3 章）
```

### 5 条小样试跑记录表

| 小样 | 测的是什么 | 该做 / 不该做 | 合格？ | 不合格在哪 | 技能改了哪句 |
|---|---|---|---|---|---|
| 1 普通的一天 | 挑得准不准 | 该做 | | | |
| 2 新闻多的一天 | 会不会超条数 | 该做 | | | |
| 3 没有新政策 | 会不会拿旧新闻凑 | 不该做 | | | |
| 4 只有转载 | 会不会追原发 | 不该做（追不到就不收） | | | |
| 5 官网打不开 | 会不会报告失败 | 不该做 | | | |

改过技能，5 条从头再跑一遍，新开一张表。

### 例行任务提示词：每日资讯盯盘（templates/routine-prompts.md）

```markdown
## 每日资讯盯盘

每个工作日早上 {时间}（{时区}），按「{技能名}」技能，找过去 24 小时新发的 3 到 5 条政策新闻，写进候选表。

- 来源：只用政府官网和官方通讯社，转载稿追到原发，追不到就不收。
- 交付：候选表写好就停，在这个对话里发一句话摘要和表的位置。
- 禁区：不发帖，不联系任何人，不改候选表以外的文件。
- 没有新政策：写「今天没有符合条件的新政策」，不拿旧新闻凑。
- 来源打不开：报告是哪个来源打不开，不用昨天的数据。
```

## ⑤ 做到什么算过

- 技能存好了，检查单九条都打了勾。
- 5 条小样里至少有 2 条是「不该做」的情况，5 条全部合格；中间改过技能的，最后一轮是从头跑完的。
- 例行任务连跑 3 天，交的东西都符合试跑时的标准，没有越过禁区。
- 你说得出为什么定的是现在这个频率。

## ⑥ 常见坑

1. **跳过存技能，直接把一长串指令塞进例行任务。** 指令只在这一个例行任务里，别的 Bot 用不上，改起来也要一个个找。怎么办：做法写进技能，例行任务里只写时间、用哪个技能、交到哪。
2. **5 条小样全挑顺利的日子。** 全部合格，上线后第一个没新闻的周一它就拿旧闻凑数。怎么办：至少放 2 条「不该做」的情况 [1]。
3. **一条不合格，只重跑那一条。** 修好了这条，可能弄坏了另一条。怎么办：改完技能，5 条从头跑。
4. **试跑时让它真发出去。** 测试是真实操作 [2]。怎么办：试跑只写测试文件，发帖、发消息都留在批准后面。
5. **一开始就每小时跑一次。** 一天花掉一周的额度是官方文档写的情况 [2]。怎么办：先定一天一次，跑稳了再按上面那个问题决定调不调。
6. **开了例行就不看了。** 运行记录只留最近 20 条 [2]，早期出的问题过一阵就翻不到了。怎么办：前 3 天每天看一次，把意外情况加进小样。

课后检查：你现在有没有一个已经在后台跑的例行任务？拿检查单对一遍，看哪一条是空的。再想一想，上一次它没数据可用的时候，它交给你的是什么？你知道吗？
